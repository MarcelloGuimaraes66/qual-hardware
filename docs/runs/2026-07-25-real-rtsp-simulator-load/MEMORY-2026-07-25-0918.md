# Memória — decisões permanentes do RTSP

1. Nunca aprovar RTSP apenas porque existe uma porta aberta.
2. Nunca persistir URL com usuário e senha.
3. O simulador aprovado é identificado pelo executável e por inferência de
   vídeo funcional; nome e hash isolados não bastam.
4. A calibração sempre repete o preflight com o cenário atual.
5. O gerador interno é útil para diagnóstico, mas não é evidência de DVR.
6. Cada câmera materializada precisa de uma sessão receptora concluída.
7. Codec, resolução, FPS e bitrate efetivos precisam cobrir o grupo.
8. Payload de loopback mede o receptor, não a NIC física.
9. Delta de RAM começa antes de criar os leitores.
10. Ausência do simulador não apaga as demais medições: bloqueia compra e
    mantém planejamento diagnóstico.
11. O simulador atual é Windows/WPF. macOS e Ubuntu devem falhar fechados até
    existir uma fonte funcional homologada nessas plataformas.
12. O MediaMTX do simulador pode escutar fora do loopback; usar somente em rede
    de teste protegida.
