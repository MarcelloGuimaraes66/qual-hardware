# Qual Hardware 0.6 — planejamento de execução

## Identidade e processo

- Repositório: `C:\dev\perceptrum_desktop_aspp\qual-hardware`.
- Produto: Qual Hardware desktop multiplataforma.
- Processo e memória: harness e contexto do Codex; Archon explicitamente excluído pelo usuário.
- Risco: T4.
- Orçamento de mudança: redesenho direcionado.
- Branch: `codex/windows-multi-cpu-gpu-capacity`.
- A implementação 0.5 ainda está no working tree e será preservada.
- `logos/` pertence ao usuário e não será alterada.

## Objetivo

Eliminar a dependência operacional de pacotes `.qhruntime`, descobrir o ambiente
local automaticamente e manter a aplicação utilizável em uma máquina limpa por
meio de um benchmark interno. O resultado genérico será sempre diagnóstico;
homologação continuará exigindo evidência Perceptrum compatível.

## Invariantes

- Uma única base para Windows x64, Ubuntu x64 e macOS ARM64.
- Nenhum download ou instalador executado automaticamente.
- Nenhuma chamada OpenAI ou tráfego externo durante calibração.
- Links externos somente após clique explícito e por identificador permitido.
- Histórico v1–v5 e `.qhcal`/`.qhcalset` v1–v3 legíveis.
- VÍDEO FULL, FRAME, busca dinâmica, multi-CPU/multi-GPU e importação preservados.
- Falha de infraestrutura nunca vira capacidade máxima.
- Codex não inicia diagnósticos físicos de 10/60 minutos nem qualificação comercial.

## Blast radius

Pode mudar: bootstrap desktop, descoberta de ambiente, kernel de calibração,
contratos, persistência aditiva, relatórios, UI de preflight, empacotamento e
helper nativo.

Não pode mudar: dados do Perceptrum, credenciais, bancos do Perceptrum,
catálogo comercial não relacionado, arquivos do usuário e formatos históricos.

## Matriz

| Plataforma | Implementação | Validação local |
|---|---|---|
| Windows x64 | completa | build, testes, pacote e smoke |
| Ubuntu 24.04 x64 | código e CI | não há host físico nesta execução |
| macOS Apple Silicon | código e CI | não há host físico nesta execução |

## Rollback

- Migração SQLite somente aditiva e precedida pelo backup já existente.
- O diretório legado `calibration-runtime` não será removido.
- Endpoints antigos ficam em transição com HTTP 410.
- Se o preflight falhar, a aplicação entra em inventário limitado em vez de
  bloquear ou usar uma capacidade inventada.
